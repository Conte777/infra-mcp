# Infra MCP

Набор MCP-серверов, дающих Claude Code доступ к инфраструктуре (postgres, k8s, grafana, redis, kafka, clickhouse), и marketplace, через который они ставятся одним плагином.

## Language

### Серверы и поставка

**Источник**:
Инфраструктурная система, к которой даёт доступ отдельный MCP-сервер: postgres, k8s, grafana, redis, kafka, clickhouse.
_Avoid_: бэкенд, интеграция, коннектор

**Сервер**:
Один бинарь, обслуживающий ровно один источник. Единица поставки и единица записи в `.mcp.json`.
_Avoid_: сервис, демон

**Профиль**:
Именованное окружение сервера (`default`, `stage`), определяющее, какой конфиг-файл он читает. Один процесс обслуживает ровно один профиль.
_Avoid_: инстанс, окружение, environment

**Подключение**:
Адрес и учётные данные экземпляра источника, заданные конфигом. Адресует источник целиком, а не отдельную базу или неймспейс — то, к чему обращается инструмент, задаётся его аргументом.
_Avoid_: сервер (это MCP-сервер), коннект, соединение

**Плагин**:
Единица установки в Claude Code: несёт `.mcp.json` со списком готовых серверов. У проекта один плагин на все источники.

**Marketplace**:
Витрина (`.claude-plugin/marketplace.json`) в этом же репозитории, через которую плагин ставится.

### Инструменты

**Read-инструмент**:
Инструмент, который только читает и никогда не меняет состояние источника. Имя начинается с префикса источника и `read` (`pg_read_query`). Предназначен для автоматического одобрения в permissions.
_Avoid_: query-инструмент, безопасный инструмент

**Write-инструмент**:
Инструмент, меняющий состояние источника. Имя содержит `write` (`pg_write_execute`). Всегда требует подтверждения пользователя.
_Avoid_: мутирующий инструмент, команда

**Бюджет вывода**:
Заданные конфигом лимиты на объём ответа инструмента (строки, байты). Превышение приводит к усечению с явной пометкой, а не к обрыву.
_Avoid_: лимит, пагинация

**Эталонный срез**:
Первый сервер (postgres), доведённый до работы end-to-end, по образцу которого делаются остальные пять.
_Avoid_: MVP, пилот

### Поведение процесса

**Ленивая инициализация**:
Соединение с источником устанавливается при первом вызове инструмента, а не при старте процесса. Сервер всегда стартует успешно; недоступность источника — результат вызова инструмента.
_Avoid_: отложенное подключение, lazy connect

**Stateless**:
Отсутствие состояния MCP-сессии между запросами: нет идентификаторов сессии, нет курсоров, живущих между вызовами. Пул соединений внутри процесса этого не нарушает — он ресурс, а не состояние диалога.

**Деградированный старт**:
Режим, в который сервер входит при отсутствующем или невалидном конфиге: набор инструментов остаётся полным, но любой вызов возвращает одну и ту же диагностическую ошибку вместо работы.
